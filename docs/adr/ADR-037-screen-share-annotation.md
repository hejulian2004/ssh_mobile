# ADR-037：屏幕共享涂鸦走会话应用通道

## 状态

Accepted。

本 ADR 扩展 [ADR-034](ADR-034-screen-share-realtime-media.md)。它不改变屏幕视频、
同意信令、会话生命周期、MediaProjection 或 H.264 路径。

## 决策

接收端在共享画面上涂鸦，Android 分享端把同一笔迹画在当前屏幕上。Windows 作为
分享端时不显示涂鸦。涂鸦不进入 H.264，也不进入 `ScreenShareConsentV2`。

Rust 只转发会话 DataChannel `ssh-mobile-realtime` 上的不透明字节。单包
1 至 4096 字节，并绑定接收侧代际。空载荷、超限、关闭的通道和旧代际失败关闭，
不结束共享。Dart 解析版本化笔迹；未知版本整包忽略。

坐标归一化到采集帧的 0..65535。接收端旋转只影响本地视图。笔迹保留到撤销、清空、
采集尺寸变化、停止、代际变化或传输断开；这些事件会清空两边并移除透明窗。

手机透明窗使用 `TYPE_APPLICATION_OVERLAY`（API 26 之前使用 `TYPE_PHONE`），
标志为不可聚焦、不可点击、不模态，并铺进屏幕区域。它不接收触摸，也不注入点击。
用户拒绝“显示在其他应用上层”时，共享继续，接收端提示对方看不见标记。

接受共享的说明写明可以画标记，但不能代替对方点击。这不是新的同意信令。

## 后果

应用通道是 `RealtimeSession` 上的字节管道。Feature 只依赖注入的传输，不出现
WebRTC 类型。透明窗归 `realtime_media_android`，挂在现有录屏前台服务旁边，
随服务销毁和插件卸载移除。坐标不进入日志、诊断或数据库。
